# 🏷️ Версионирование SDK

## Обзор

SDK использует систему версионирования для обеспечения обратной совместимости между плагинами и сервером. Это позволяет:

- 🔄 **Обратную совместимость** - старые плагины продолжают работать с новыми версиями сервера
- 📊 **Мониторинг версий** - отслеживание какие плагины используют какие версии SDK
- 🚀 **Эволюцию SDK** - добавление новых функций без breaking changes
- 🛡️ **Контроль совместимости** - предотвращение проблем с несовместимыми версиями

## Текущая версия

**Актуальная версия SDK: `v1.0.6`**

## Как это работает

### 1. Плагин сообщает версию SDK

Плагин должен реализовать интерфейс `VersionedPlugin`:

```go
import "github.com/metalmon/yapay-sdk"

type MyPlugin struct {
    merchant *yapay.Merchant
    logger   *logrus.Logger
}

// Обязательная реализация для версионирования
func (p *MyPlugin) GetSDKVersion() string {
    return "1.0.6"  // Версия SDK, против которой собран плагин
}
```

### 2. Сервер определяет совместимость

При загрузке плагина сервер:
- Вызывает `GetSDKVersion()` у плагина
- Проверяет совместимость с текущей версией сервера
- Логирует информацию о версии плагина
- Предупреждает о несовместимых версиях

### 3. Fallback для старых плагинов

Если плагин НЕ реализует `VersionedPlugin`:
- Сервер выводит предупреждение в лог
- Предполагает версию `1.0.6` по умолчанию
- Плагин продолжает работать нормально

## Как определить версию SDK

### Из go.mod плагина
```bash
cd your-plugin/
grep "github.com/metalmon/yapay-sdk" go.mod
```

### Из кода SDK
```go
import "github.com/metalmon/yapay-sdk"

fmt.Println(yapay.SDKVersion)  // "1.0.6"
```

## Мониторинг версий

### API Endpoint
```bash
curl http://localhost:8080/api/v1/health/plugin-versions
```

Ответ:
```json
{
  "plugins": [
    {
      "name": "sample-plugin",
      "version": "1.0",
      "sdk_version": "1.0.6",
      "is_versioned": true
    }
  ],
  "supported_sdk_versions": ["1.0.6", "1.1.0"],
  "sdk_version": "1.0.6"
}
```

### Логи сервера
```
time="2025-09-21T06:05:24+04:00" level=info msg="Plugin SDK version detected" 
  client_id=sample-plugin plugin_version=1.0 sdk_version=1.0.6 is_versioned=true
```

## Рекомендации для разработчиков

### ✅ Обязательно
1. **Всегда реализуйте** `GetSDKVersion()` в новых плагинах
3. **Тестируйте совместимость** с разными версиями сервера
4. **Обновляйте версию** при обновлении SDK

### ⚠️ Важно
2. **Документируйте изменения** при обновлении версии SDK
3. **Проверяйте breaking changes** при обновлении major версии
4. **Используйте semantic versioning** для версий плагинов

### 🔧 Примеры

#### Правильная реализация
```go
func (p *MyPlugin) GetSDKVersion() string {
    return "1.0.6"  // Точная версия из go.mod
}
```

#### Неправильная реализация
```go
func (p *MyPlugin) GetSDKVersion() string {
    return "latest"     // ❌ Неопределенная версия
    return "1.0"        // ❌ Неточная версия
    return "v1.0.6"     // ❌ Лишний префикс "v"
}
```

## Миграция старых плагинов

### Шаг 1: Добавить интерфейс
```go
// Добавить к существующему плагину
func (p *OldPlugin) GetSDKVersion() string {
    return "1.0.6"  // Версия SDK, которую использует плагин
}
```

### Шаг 2: Проверить совместимость
```bash
# Пересобрать плагин
make build-plugins

# Проверить версии
curl http://localhost:8080/api/v1/health/plugin-versions
```

### Шаг 3: Обновить документацию
Обновить README плагина с информацией о поддерживаемой версии SDK.

## Troubleshooting

### Проблема: Плагин не загружается
```
error="plugin was built with a different version of package golang.org/x/sys/unix"
```

**Решение**: Пересобрать плагин с тем же окружением:
```bash
make build-plugins  # Использует эталонный Docker образ
```

### Проблема: Несовместимая версия SDK
```
error="plugin SDK version 2.0.0 is not yet supported"
```

**Решение**: Обновить SDK до поддерживаемой версии или дождаться поддержки новой версии.

### Проблема: Плагин не сообщает версию
```
level=warning msg="Plugin does not implement VersionedPlugin interface, assuming SDK version 1.0.6"
```

**Решение**: Добавить реализацию `GetSDKVersion()` в плагин.
